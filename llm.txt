# WCH Touch Driver fork: agent reference

Start with README.md. Detailed installation is in docs/setup.md, hardware and verification in docs/compatibility.md, and restoration behavior in docs/desktop-restoration.md. Read CONTRIBUTING.md for development and SECURITY.md for privacy. Read THIRD_PARTY_NOTICES.md and preserve LICENSE and upstream Git history.

This is cryptoteatime's fork of mrnocreativity/xeneon-wch-touchscreen-driver-macos at 707106e828d178db004a7ec1b3d8eee9447b03b9, descended from ajvwhite/MacXeneonEdgeTouchDriver.

Build with python3 Scripts/build-app.py. Install with ./Scripts/install.sh --profile portable-dual-wch (new portable setup) or --profile xeneon (original defaults). Existing config is preserved. Tests: swift test and python3 Scripts/test-regressions.py. WCH_SDK_PATH can select an already installed compatible SDK.

The app and LaunchAgent intentionally keep com.ajvwhite.MacXeneonEdgeTouchDriver to avoid duplicate HID owners. Do not run a second driver instance to query status; use the installed executable's status/layout-status control commands.

Accessibility and Input Monitoring must be approved locally. Never enter a user's password or bypass macOS approval. Do not reset permissions, remove pairings or change cabling without a concrete need.

Desktop restoration uses local private window fingerprints, never readable titles or URLs. A full monitor-set match precedes restoration. Reopened app windows are matched uniquely, with a single-window app fallback; ambiguous windows are skipped. macOS must reopen the apps/windows after login. Do not claim a cold boot was tested based only on process-identity fixtures.

Never commit runtime profiles, layouts, pairings, identity salt, diagnostic logs, private screenshots or credentials. Examples in Profiles are generic hardware preferences only. Document every tested hardware configuration and distinguish inherited features from fork additions.
